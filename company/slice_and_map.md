Go Slice & Map 底层核心面试记忆点
一、Slice 必背核心记忆点
1. 底层结构体：`ptr(底层数组指针) + len(实际长度) + cap(容量)`
2. 引用类型，赋值、函数传参都是浅拷贝，共用同一份底层数组
3. 切片截取 `s[low:high]`：与原切片共享底层数组，修改互相影响
4. 扩容规则：

  - 元素长度 < 1024：翻倍扩容
  - 元素长度 ≥ 1024：1.25倍扩容
5. 触发扩容会新建底层数组，旧数组无引用后被GC回收
6. nil切片：`var s []int`，ptr为nil，len=0、cap=0，不能直接赋值元素
7. 空切片：`s := []int{}`，ptr有内存地址，len=0、cap=0
8. append触发扩容后，新切片与原切片内存分家，修改互不影响
二、Map 基础固定参数（必记）
1. 每个桶（bmap）固定存放 8个 KV 键值对
2. 桶总数固定公式：桶总数 = 2^B
3. 负载因子固定阈值：6.5
4. 哈希冲突解决方式：拉链法 + 溢出桶
5. 桶寻址方式：哈希值低B位 `& (桶总数-1)` 位运算快速定位
三、Map 扩容规则
1. 翻倍扩容
- 触发条件：元素总数 / 桶总数 > 6.5
- 动作：`B = B + 1`，桶总数直接翻倍
- 目的：增加桶数量，降低单个桶负载
2. 等量扩容
- 触发条件：负载因子未超6.5，但溢出桶数量过多、拉链链表过长
- 动作：B不变、桶总数不变，重新规整所有key
- 目的：清理空溢出桶、缩短链表，提升查询性能
3. 渐进式扩容
- 不会一次性迁移所有桶数据
- 每次增删查改map时，顺带搬迁1~2个旧桶
- 避免大批量迁移造成服务卡顿
四、Map 底层核心细节
1. tophash：桶内存储哈希高8位，先比对高8位快速过滤，再完整对比key，提升查找效率
2. 遍历无序：遍历起始桶随机 + 扩容后key重哈希分布，官方刻意不保证遍历顺序
3. Key类型限制：必须是可比较类型；slice、map、func 不可比较，不能作为map的key
4. 零值nil map：仅能读、遍历、取len，直接写入会panic
5. 赋值特性：map赋值是浅拷贝，只拷贝hmap头结构，共用底层桶与溢出桶
6. 并发安全：原生map非并发安全，并发读写直接panic；解决方案：`sync.RWMutex`、`sync.Map`
7. 删除特性：删除key仅标记位置为空，不回收溢出桶、不截断链表；反复插入删除会堆积超长溢出链表，触发等量扩容
8. 预分配优势：`make(map[k]v, 预估元素数)` 预分配容量，减少扩容与渐进迁移开销，提升性能
五、高频面试浓缩口诀
Slice
底层ptr len cap，引用浅拷贝共享数组；
截取互相影响，千内翻倍千二五；
扩容换新数组，nil空切片有区别，扩容之后就分家。
Map
每桶八个KV，桶数二的B次方；
负载六点五超了翻倍扩，溢出桶多等量规整；
拉链解决哈希冲突，高位hash快速匹配；
渐进扩容不卡顿，遍历无序key要可比较；
零值不可写、赋值浅拷贝，并发不安全、插删堆溢出链。
