# 缓存与消息队列（口述问答）

> 对应 `readme.md` 中「缓存 & 消息队列」：Redis、Kafka、Asynq。

## 1) Redis 常见数据结构你怎么选型？

**口述参考：**  
String 做缓存与计数；Hash 存对象字段；List 做队列或时间线；Set/ZSet 做去重与排行榜；Bitmap/HyperLogLog 做统计。选型要结合内存、过期策略与操作复杂度。

## 2) Redis Cluster 下 key 设计要注意什么？

**口述参考：**  
hash tag 控制同一槽位，避免大 key 和热 key。跨槽多键操作受限，事务和 lua 要保证 key 同槽。故障切换时要理解复制与脑裂窗口对一致性的影响。

## 3) 分布式锁用 Redis 怎么做才相对可靠？

**口述参考：**  
用唯一 token + Lua 释放，设置合理 TTL 防止死锁，续期用看门狗模式要谨慎。Redlock 有争议，金融强一致更倾向 etcd 或 DB 锁。业务上尽量缩短临界区。

## 4) 缓存穿透、击穿、雪崩分别怎么处理？

**口述参考：**  
穿透用布隆过滤或空值短期缓存；击穿用互斥重建或 singleflight；雪崩用随机 TTL、预热与限流。核心链路要有降级开关，避免缓存故障拖垮 DB。

## 5) Kafka 分区内有序、消费语义你怎么讲清楚？

**口述参考：**  
Kafka 只保证分区内顺序，全局有序要业务层代价。消费语义上多数业务用 at-least-once 加幂等；处理成功再提交 offset。重平衡会带来短暂停顿和重复，要有监控。

## 6) Kafka 生产端 acks、重试与幂等你怎么配？

**口述参考：**  
高可靠用 `acks=all` 配足够 ISR；生产端开启幂等生产者减少重复分片内写入。消费端幂等靠业务唯一键。重试要区分可重试错误与 poison message，必要时进 DLQ。

## 7) Asynq（或类似队列）适合解决什么问题？

**口述参考：**  
适合异步任务、定时任务、削峰填谷，比如索引构建、通知、批处理。要定义重试策略、超时、并发 worker 数和死信处理，任务 payload 尽量小、可序列化版本化。

## 8) 消息队列与数据库双写一致性你怎么做？

**口述参考：**  
优先 outbox 表：本地事务写业务表 + 事件表，异步投递到 MQ，消费者幂等处理。避免「先写库再发消息」无事务保证的裸操作，除非可接受短暂不一致。

## 9) Redis 与 DB 不一致窗口怎么接受与补偿？

**口述参考：**  
先明确业务容忍度。常见先写 DB 再删缓存，失败重试；读路径可带版本号。强一致场景缩短窗口或用同步读主，Agent 场景多最终一致 + 用户侧刷新策略。
