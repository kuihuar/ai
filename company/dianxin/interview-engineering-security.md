# 工程化与安全（口述问答）

> 对应 `readme.md` 中「工程规范」与软技能中的协作、Code Review；含 JWT、API Key。

## 1) Git 协作分支策略你怎么选？

**口述参考：**  
小团队可用 trunk-based 加短生命周期 feature 分支；发布节奏慢可用 GitFlow 变体。关键是 code review 门槛、CI 必须通过、main 可回滚。冲突频繁时缩短分支寿命与拆分 MR。

## 2) JWT 结构里哪些字段你会用？有什么安全注意点？

**口述参考：**  
sub、exp、iat、可选 aud/scope。密钥轮换、短过期 + refresh 或服务端会话黑名单看场景。敏感信息不放 payload 明文；HTTPS 传输；防 CSRF 对 cookie 场景要配套。

## 3) API Key 和 JWT 分别适合什么场景？

**口述参考：**  
API Key 适合服务间、脚本、长期集成，配合权限范围与速率限制；JWT 适合用户态、可携带声明、无状态校验。Agent 平台可能对插件或开放 API 用 scoped API Key，对用户会话用 JWT。

## 4) 如何做 API 鉴权与限流的分层？

**口述参考：**  
网关做粗粒度限流与 TLS，服务内做细粒度 RBAC 与配额。限流算法令牌桶/漏桶看突发容忍度，分布式限流用 Redis 或网关能力，注意时钟与竞争。

## 5) golangci-lint / gofmt 在团队里怎么落地？

**口述参考：**  
CI 强制 lint 与测试，本地 pre-commit 可选；规则集团队评审固化，避免个人随意关规则。格式化统一 gofmt/goimports，减少无意义风格争论。

## 6) Code Review 你最关注什么？

**口述参考：**  
正确性与边界、错误处理、并发安全、性能与可观测性、API 向后兼容。评论要具体可改，大块变更要求设计说明。目标是风险前置而不是挑刺。

## 7) 你如何推动跨团队排障？

**口述参考：**  
先同步现象与影响面，拉齐时间线和变更记录，指定 owner 和沟通频道。用 trace id 串日志，避免信息碎片化。结论写简短复盘，行动项跟 owner 和 deadline。

## 8) 独立负责模块时你怎么保证交付质量？

**口述参考：**  
需求阶段澄清验收标准与风险；设计文档或 ADR 记录取舍；开发阶段单测覆盖关键路径；上线灰度与监控对照；上线后观察一段时间再关工单。

## 9) 敏感配置与密钥管理你怎么做？

**口述参考：**  
不进仓库，用 KMS 或 Secret 管理，运行时注入。日志脱敏，错误信息对外与对内分层。定期轮换密钥与最小权限原则。
