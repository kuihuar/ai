# 数据库与 ORM（口述问答）

> 对应 `readme.md` 中「数据库」：MySQL、MongoDB、GORM。

## 1) MySQL 索引你怎么设计？联合索引顺序怎么定？

**口述参考：**  
先看查询条件与排序字段，把高选择性、等值条件放前面，范围条件往后。避免过多冗余索引，写放大要权衡。上线前用 `EXPLAIN` 验证是否命中预期索引、是否回表过多。

## 2) 事务隔离级别在实际项目里怎么选？遇到过什么问题？

**口述参考：**  
默认 RR 在 MySQL 里较常见，但要清楚幻读与 gap lock 带来的锁范围扩大问题。只读报表可用 RC 或只读副本。关键账务会显式 `SELECT ... FOR UPDATE` 并缩短事务，避免长事务锁表。

## 3) 死锁或锁等待超时你怎么排查？

**口述参考：**  
先看 `SHOW ENGINE INNODB STATUS` 或 performance_schema，找等待链和 SQL。业务上统一资源加锁顺序、拆批、避免事务里调外部 RPC。修复后补慢 SQL 与锁等待监控。

## 4) MongoDB 和 MySQL 你怎么分工？

**口述参考：**  
强一致、复杂事务、关系模型清晰用 MySQL；文档形态多变、横向扩展与嵌套结构用 Mongo。Agent 场景里会话元数据、非结构化日志可放 Mongo，计费与订单仍放关系库。

## 5) MongoDB 聚合管道用在什么场景？

**口述参考：**  
适合在库侧做分组统计、漏斗分析、轻量 ETL。注意 `$lookup` 大集合性能和内存限制，必要时落离线数仓。索引要配合 pipeline 的 `$match` 前置过滤。

## 6) GORM 的 Hook 你怎么用？有什么坑？

**口述参考：**  
Hook 适合统一审计字段、软删除、默认值，避免在 Hook 里写重逻辑或远程调用，否则事务边界难控。注意回调注册顺序和 N+1，`Preload` 要明确关联。

## 7) GORM 预加载（Preload）和 Join 怎么选？

**口述参考：**  
一对多用 `Preload` 可读性好，但要防 N+1 和过多 round trip；列表页大批量时可能改手写 join 或分批。始终打开 SQL 日志在测试环境验证语句条数。

## 8) GORM 事务边界你怎么划？

**口述参考：**  
事务只包必须原子的 DB 操作，不放 HTTP/RPC。跨服务用最终一致：本地事务 + 消息表或 outbox。GORM 里用 `Transaction` 闭包，错误统一返回，避免吞 err。

## 9) 慢 SQL 优化的一般路径？

**口述参考：**  
从慢日志定位 SQL，看扫描行数与索引命中，优化 where 顺序与索引、分页方式（游标/seek）、减少 select *。数据量大时考虑归档或读写分离，并用压测验证 P99。
