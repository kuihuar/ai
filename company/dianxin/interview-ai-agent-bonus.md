# AI Agent 平台与加分项（口述问答）

> 对应 `readme.md` 中「工作方向」与「加分项」：Agent 平台、向量库、CloudWeGo / Eino、其它中间件等。

## 1) 你怎么理解 AI Agent 平台后端的核心职责？

**口述参考：**  
不仅是包一层大模型 API，还要负责会话与状态、工具调用编排、权限与审计、异步任务与可观测。后端要保证延迟可控、成本可控、失败可恢复，并把「一次 agent 运行」做成可追踪的事务或工作流。

## 2) 对话与知识库结合时，架构上怎么拆分？

**口述参考：**  
对话服务负责会话、鉴权、流式输出；检索服务负责 embedding、向量检索与重排；内容管理负责文档入库与版本。异步建索引走队列，读路径缓存热点检索结果，注意权限过滤在服务端做。

## 3) RAG 链路里延迟和一致性你怎么优化？

**口述参考：**  
并行检索、缓存 query embedding、限制 topK 与片段大小；写路径 eventual consistency，读路径带版本号或「索引未完成」提示。对长文档分块策略与元数据要可配置、可观测。

## 4) 向量数据库（Milvus / Weaviate / Pinecone）选型你会看什么？

**口述参考：**  
数据规模、延迟与召回要求、运维成本、多租户与权限、混合检索能力。云上托管省运维，自研 Milvus 要投入集群与监控。要评估过滤条件、标量字段与索引类型（HNSW 等）的 trade-off。

## 5) Agent 调外部工具（tool calling）后端要注意什么？

**口述参考：**  
超时、重试、幂等、权限最小化、参数校验防注入。工具结果可能很大，要截断与结构化存储。全链路记录 tool 名、参数摘要、结果摘要用于审计与排障（注意脱敏）。

## 6) 长上下文与 token 成本你怎么在服务端控制？

**口述参考：**  
摘要历史、滑动窗口、分层记忆（短期会话 + 长期用户画像异步更新）。对模型调用设 max_tokens、并发与队列，防止成本爆。计费与配额在网关或 BFF 统一扣减。

## 7) CloudWeGo Hertz / Kitex 与 Kratos / Eino 你有何了解？

**口述参考：**  
CloudWeGo 偏字节系微服务组件，Hertz HTTP、Kitex RPC，生态里中间件较全。Kratos 偏工程化分层与插件。Eino 偏 AI 应用编排（若简历有则展开实际项目模块）。没有深度用过就诚实说边界，强调可迁移的设计能力。

## 8) ClickHouse 适合什么负载？和 MySQL 怎么配合？

**口述参考：**  
适合海量 append-only 分析、漏斗、日志聚合；不适合高频小事务更新。常见是业务写 OLTP，异步同步或埋点到 ClickHouse 做报表，注意去重与分区键设计。

## 9) Nacos 你在配置中心场景怎么用？

**口述参考：**  
动态配置下发、灰度开关、服务发现（若用）。注意配置变更的监听风暴与本地缓存一致性，关键配置要有默认值与校验，变更可审计。

## 10) WASM（如 wazero）在后端可能的应用？

**口述参考：**  
沙箱执行用户或插件逻辑、可热更新策略、跨语言扩展。要注意资源限制（内存 CPU）、宿主 ABI 安全、禁止危险 syscall。没有生产经验就说明仅调研或 PoC。

## 11) 多数据库适配你怎么抽象？

**口述参考：**  
仓储层接口隔离具体驱动，迁移用版本化脚本（如 golang-migrate），读写路径避免 ORM 泄漏到业务层。切换数据库时重点测事务语义与类型差异。

## 12) 开源或技术博客你如何介绍给面试官？

**口述参考：**  
一句话说清问题与方案，给仓库链接或文章结构：背景、设计、benchmark、踩坑。强调维护状态和社区反馈，避免只罗列 star 数。
