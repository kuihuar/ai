## 二、商业与战略

### 2.1 题库的商业本质

**题库是什么？** 不是一个"存储题目的数据库"，而是一个**教育内容资产平台**。

它的商业价值体现在三个层面：

| 层面 | 价值 | 类比 |
|------|------|------|
| **直接变现** | 卖会员、卖课程、卖服务 | 内容付费 |
| **流量入口** | 学生搜题 → 引流到其他服务（补课、卖书、卖课） | 搜索引擎模式 |
| **数据资产** | 学生的搜索行为、错题数据 → 最精准的学习画像 | 数据变现 |

**你的核心资产到底是什么？**

不是题目本身（题目谁都能搞），而是：
1. **结构化知识体系**：知识点树 + 题目-考点精确映射（别人半年追不上）
2. **高质量解析库**：经过人工审核 + 用户验证的版本（信任壁垒）
3. **用户行为数据**：哪道题被搜最多、哪种解法被 👍 最多、学生在哪个知识点卡住（数据飞轮）

### 2.2 护城河分析

| 护城河类型 | 具体是什么 | 可持续性 | 投入 |
|------------|-----------|----------|------|
| 题库数量 | 千万级题库 | 低（竞品也能攒） | 中 |
| 解析质量 | 每道题经过审核 | 中（需要持续投入） | 高 |
| 知识体系 | 精准的知识点标签 + 教材映射 | **高（时间壁垒）** | 高 |
| 用户行为数据 | 搜索/纠错/偏好数据 | **极高（数据飞轮）** | 极高（需大量用户） |
| 品牌信任 | "这个 App 的答案一定对" | **极高** | 极高（一次错误就丢信任） |
| 生态网络 | 教师/内容创作者/学校合作 | **高（网络效应）** | 极高 |

**判断护城河是否成立的一个问题**：如果竞品拿到你全部题目的 JSON 导出文件，他们能多快追上来？

- 如果答案是一个月 → 你没护城河
- 如果答案是两年 → 你有护城河（知识体系 + 数据 + 品牌）

### 2.3 收入模型设计

| 模式 | 做法 | 适用 |
|------|------|------|
| **Freemium** | 基础搜题免费，精美解析/举一反三/错题本付费 | C 端产品 |
| **学校/机构 SaaS** | 题库 API + 教学管理系统，按学生数收费 | B 端 |
| **内容授权** | 出版社/在线教育平台按题或按次付费调用 | B 端 |
| **广告** | 搜题结果中插教育类广告 | C 端（体验差） |
| **数据服务** | 脱敏后的学情数据报告（给教育局/学校） | G 端 |

**典型路径**：C 端免费聚用户 → 数据飞轮转起来 → B 端变现（学校/机构）。

### 2.4 竞品态势分析

你必须持续关注四类玩家：

| 类型 | 代表 | 优势 | 威胁 |
|------|------|------|------|
| **垂直题库产品** | 作业帮、小猿搜题 | 题库壁垒深、用户多 | 直接竞争 |
| **大模型公司** | OpenAI、DeepSeek | 零题库也能解题 | **颠覆性威胁** |
| **内容平台** | 抖音教育、B站 | 流量优势 | 截流入口 |
| **传统出版** | 人教社、各类教辅 | 版权内容壁垒 | 内容上游 |

**大模型公司的威胁是最值得警惕的**。如果 GPT-5 能直接拍照解题，且准确率 99%，为什么还需要题库？

→ 这也是你必须思考的"终局问题"。

## 三、组织与团队

### 3.1 团队结构

```
题库 Owner
├── 内容团队（教研员 3-10 人）
│   ├── 题目录入/审核
│   ├── 知识点体系维护
│   └── 解析质量控制
│
├── 工程团队（5-15 人）
│   ├── 后端：检索/存储/管线
│   ├── 算法：NLP/CV/Embedding/LLM
│   ├── 前端：审核后台/录入工具
│   └── 数据工程：抓取/清洗/ETL
│
├── AI 团队（2-5 人）
│   ├── Prompt 工程
│   ├── LLM 效果评估
│   └── 自动验收系统
│
├── 产品经理（1-2 人）
│   ├── 用户需求、增长策略
│   └── 跨部门协调
│
└── 运营（1-2 人）
    ├── 内容运营（热门题追踪、缺题补全）
    ├── 用户反馈运营
    └── 合作方沟通
```

### 3.2 你（Owner）的核心职责

不是"管理"，而是：

| 职责 | 具体做什么 | 频次 |
|------|-----------|------|
| **定义质量标准** | "什么叫一道好题？什么叫一个好解析？" 必须有明确标准 | 一次性，定期修订 |
| **决策 tradeoff** | 速度 vs 质量，AI 自动 vs 人工审核，广度 vs 深度 | 持续 |
| **沟通业务方** | 和产品/运营/市场对齐：题库要支撑什么业务目标？| 每周 |
| **技术方向** | 管线式还是端到端？用哪个 LLM？什么时候重构？ | 每月 |
| **看数据** | 关注核心指标（覆盖率、准确率、成本），从数据发现机会 | 每天 |
| **看竞品** | 他们的题库在做什么？有什么新玩法？ | 每周 |
| **培养团队** | 让教研员懂 AI 工具，让工程师懂教育场景 | 持续 |
| **想未来** | LLM 越来越强，题库的价值锚点是什么？ | 持续 |

### 3.3 跨团队协作

你作为"题库方"，对外接口有哪些？

```
你（题库 Owner）
    │
    ├── → 产品团队："下个月要上什么功能？题库需要配合什么？"
    │
    ├── → 运营团队："最近搜索 top 100 没有解析的是哪些？优先级是什么？"
    │
    ├── → AI/算法团队："新的 embedding 模型评测完了，什么时候替换？"
    │
    ├── → 市场/商务："和 XX 出版社谈了题库交换，帮我看下格式能不能接？"
    │
    ├── → 法务/合规："抓取 XX 网站的公开题目，法律风险多大？"
    │
    ├── → 客服/用户反馈："用户报错的题，处理时效是什么？"
    │
    └── → 你的老板："这季度题库的核心指标是什么？预算够吗？"
```

## 四、产品与用户

### 4.1 用户分层

不是所有用户的需求都一样：

| 用户类型 | 核心需求 | 对题库的要求 |
|----------|----------|-------------|
| 初中生 | 快速查答案 | 准确率 > 速度 > 深度 |
| 高中生 | 理解解题过程 | 步骤完整 > 多解 > 准确率 |
| 家长 | 辅导孩子 | 讲解清晰、有知识点说明 |
| 老师 | 备课找题、出卷 | 知识点筛选、难度可控、可导出 |
| 教研员 | 题库建设 | 录入工具、审核流程、质量统计 |

**题库的产品形态对不同用户应该是不同的**。

### 4.2 核心体验指标

| 指标 | 定义 | 初中生目标 | 老师目标 |
|------|------|-----------|----------|
| 搜索到结果的时间 | 拍照 → 看到答案 | < 2s | < 3s |
| 答案正确率 | 用户 👎 率 | < 2% | < 1% |
| 解析可读性 | 能看懂的比例 | > 90% | > 95% |
| 题库覆盖率 | 搜的题有答案的比例 | > 85% | > 70% |
| 首次搜题成功率 | 一次就找到的比例 | > 80% | > 75% |

### 4.3 数据飞轮

```
用户搜题 → 行为数据 → 发现热门缺题 → 优先补全
                              ↓
用户纠错 → 错误数据 → 改进解析 → 新解析入库
                              ↓
用户 👍/👎 → 质量数据 → 评分排序 → 好解析排名上升
                              ↓
        ←── 更好体验 ←── 更多用户 ←──┘
```

**飞轮一旦转起来，竞品很难追上，因为他们没有你的用户行为数据。**

## 五、技术架构（作为 Owner 的关注点）

你不必写每一行代码，但你必须对以下技术决策有判断：

### 5.1 你必须在意的技术决策

| 决策 | 为什么重要 | 你的判断依据 |
|------|-----------|-------------|
| 存储选型 (PG vs MySQL vs 自研) | 影响扩展、查询、运维成本 | 当前量 + 3 年预估量 |
| 检索架构 | 直接影响用户体验（搜不搜得到） | 准确率 + 延迟 + 成本 |
| LLM 怎么用 | 成本和质量的天平 | 按场景分级，不是所有题都要最强模型 |
| 微服务 vs 单体 | 影响开发速度、部署复杂度 | 团队规模和业务复杂度决定 |
| 自研 vs 开源 | 影响研发效率和可控性 | 开源够用就不用自研 |

### 5.2 技术债务管理

题库系统的技术债务有特殊的形态：

| 债务类型 | 表现 | 不及时还的后果 |
|----------|------|---------------|
| **数据债务** | 分类标注错误、重复题未合并 | 检索精度下降，用户搜不到 |
| **模型债务** | embedding 模型老旧、LLM prompt 未更新 | 搜索和生成质量退化 |
| **架构债务** | 单表过大、索引失效 | 搜索变慢，用户流失 |
| **流程债务** | 审核流程不畅、自动验收规则过时 | 低质内容入库 |

**还债策略**：每个迭代花 20% 时间修数据，20% 时间修代码（技术债），60% 时间做新功能。

## 六、治理与合规

### 6.1 内容安全

教育类产品的内容安全有单独的审查维度：

| 审查类型 | 检查内容 | 工具 |
|----------|----------|------|
| 题目内容合规 | 不得有意识形态问题、政治隐喻 | LLM + 关键词 |
| 答案正确性 | 不得有科学性错误 | 符号验证 + 人工抽检 |
| 价值观审查 | 例题中不得有不健康的价值观 | LLM + 人工 |
| 图片安全 | 涉黄涉暴涉政 | API（阿里云/腾讯云内容安全） |
| 版权检测 | 题目是否涉及侵权 | 相似度检测 + 来源标注 |

### 6.2 数据隐私（红线）

**学生数据是最高敏感级别的数据。** 在中国，涉及《个人信息保护法》和教育部相关规定。

| 数据 | 处理要求 |
|------|----------|
| 用户搜索历史 | 加密存储，脱敏后方可用于分析 |
| 用户错题本 | 属于个人敏感信息，用户可导出/删除 |
| 用户拍照图片 | 处理后立即删除原图，只保留题目文本 |
| 用户行为分析 | 匿名化后才能用于模型训练或统计 |
| 未成年人数据 | 遵守《儿童个人信息网络保护规定》 |

### 6.3 教育政策敏感性

- 双减政策下，拍照搜题类产品曾被点名。题库可能被要求配合"不得直接给答案"
- 教材改版（新课标）→ 题库必须跟上，否则题目全部"过时"
- 高考改革 → 题型变化 → 题库策略需要调整

**应对**：保持和教研员/教育系统的联系，提前拿到教材改版消息，有缓冲期更新题库。

## 七、生态与合作

### 7.1 从"自己搞"到"平台化"

```
Phase 1：自己搞
  自有录入 + 抓取补充

Phase 2：合作
  出版社、教辅机构、学校合作获取内容

Phase 3：平台化
  开放题库 API → 第三方产品接入
  开放"解析贡献者"体系 → 老师/教研员贡献解析获取收益
  开放"题目纠错"众包 → 用户反馈驱动质量提升
```

### 7.2 两端市场

如果把题库看作一个"题目-解析"的交易市场：

```
供方（内容生产者）         需方（内容消费者）
  - 老师                    - 学生
  - 教研员                  - 家长
  - 出版社                  - 在线教育平台
  - AI（生成）              - 学校
```

**平台的价值是撮合**：让老师贡献的解析被更多学生看到，让出版社的题目在平台上获得流量和收益。

## 八、未来与终局

### 8.1 五年后的题库是什么样子

| 今天 | 五年后 |
|------|--------|
| 搜题 → 给答案 | 搜题 → **AI 导师对话**（不直接给答案，引导你自己做） |
| 静态解析 | **动态交互式解析**（每一步可展开、可追问、可切换解法） |
| 题目是文本 | 题目是**多媒体对象**（3D 几何模型、物理仿真动画） |
| 按知识点的题库 | **按能力的题库**（不只是考知识点，考思维/素养） |
| 题库数据不互通 | **学情全景图**（题库使用数据 + 考试成绩 + 课堂表现） |

### 8.2 LLM 终局之问：如果 AI 能 100% 准确解题，题库还有价值吗？

**有价值，但价值锚点会变。**

| 题库的价值锚点 | 今天 | LLM 能解题后 |
|---------------|------|-------------|
| 提供"正确答案" | 核心价值 | 不再值钱 |
| 经过审核的确定性 | 重要 | **更值钱**（你无法信任 AI 100%） |
| 知识点精准映射 | 重要 | **更值钱**（LLM 不懂教学大纲） |
| 用户行为数据 | 已经值钱 | **最值钱**（知道学生哪里卡住） |
| 个性化学习路径 | 探索中 | **核心壁垒** |

**类比**：
- Google 能搜到一切信息 → 维基百科仍然值钱（**经过整理的确定性知识**）
- ChatGPT 能回答一切问题 → Stack Overflow 仍然值钱（**经过社区验证的确定性答案**）
- LLM 能解一切题 → **经过教研员审核的、精准对应考点的、被千万学生验证过的**题库，仍然值钱

**核心竞争力不是"有答案"，而是"这个答案你可以完全信任"以及"我知道你错在哪"**。

### 8.3 终局推演

三条路径：

```
路径 A：被大模型替代
  LLM 准确率 → 99.9%，题库价值归零
  应对：转型为"教育 AI 教练"，题库数据作为训练数据或 RAG 知识库

路径 B：与 LLM 共生
  LLM 负责生成 → 题库负责验证 + 审查 + 结构化
  题库是 LLM 的"ground truth 锚点"

路径 C：成为基础设施
  题库成为教育行业的"水电煤"
  所有教育产品默认接入你的题库 API
  你的知识体系成为行业标准
```

**路径 B 是最现实的**：LLM 不会取代题库，但"没有 AI 的题库"会被"有 AI 的题库"取代。

### 8.4 你应该持续关注的前沿

| 技术趋势 | 对题库的影响 | 关注度 |
|----------|-------------|--------|
| 多模态大模型更强 | 图像可以直接变解答，OCR 退化 | ⭐⭐⭐⭐⭐ |
| Agent 能力增强 | 多步推理更可靠，长题解答更准确 | ⭐⭐⭐⭐ |
| 端侧模型（Apple Intelligence 等） | 拍照搜题本地完成，不经过服务端 | ⭐⭐⭐⭐ |
| AI 导师/家教 | 搜题变成对话，题库数据结构需要变化 | ⭐⭐⭐⭐⭐ |
| 自适应学习 | 题库不只是搜，要根据学生能力自动选题 | ⭐⭐⭐⭐ |
| AR/VR 教育 | 题目展示形式从 2D 变成 3D | ⭐⭐ |
| 教育大模型 | 专门为教育场景微调的基础模型 | ⭐⭐⭐⭐⭐ |
| AI 生成题目 | 题库的"生产端"AI 化 | ⭐⭐⭐⭐ |

## 九、自我拷问：作为 Owner 必须能回答的 20 个问题

**关于产品**：
1. 如果竞品明天免费，我们凭什么活下去？
2. 用户为什么要相信我们的答案是正确的？
3. 题库最核心的 3 个体验指标是什么？现在分别是多少？
4. 用户搜不到题的时候，我们的兜底体验是什么？

**关于技术**：
5. 搜索延迟从 200ms 降到 50ms，能带来多少用户留存提升？值得投入吗？
6. 数据库单表到多少行会出问题？什么时候要分表？
7. 如果 LLM 服务全部宕机，题库还能正常工作吗？
8. 我们现在的 embedding 模型是目前最好的吗？上次换模型是什么时候？

**关于团队**：
9. 团队里有多少人知道题库的整体架构（不仅仅是自己的模块）？
10. 如果你明天不在，谁能接手？文档够吗？
11. 教研员的效率能不能用 AI 工具再提升 50%？

**关于商业**：
12. 题库的直接成本（人力+LLM+服务器）/月是多少？单位成本（每道题）是多少？
13. 一道"热门题"（日搜索 > 1000）带来的商业价值是多少？一道"冷门题"的成本是挣回来的还是亏的？
14. 竞品的题库数量和我们的差距是扩大还是缩小？

**关于未来**：
15. 如果教材全面改版，题库需要多久能更新完？
16. 三年后，学生搜题的行为会变成什么样？
17. 如果国家禁止拍照搜题直接给答案，题库产品如何转型？
18. 题库数据作为 AI 训练数据的价值，现在开发了吗？
19. 有没有可能把题库做成"教育行业的知识图谱标准"？
20. **你做题库，到底是为了什么？**（帮助学生学习？商业成功？还是两者？当两者冲突时，你选什么？）
