# 02. LLM / RAG 工程化口述题

## 1) 介绍一个你做过的 RAG 落地项目

**口述主答（90~120 秒）：**  
我做过一个“事件库 + 自定义报告”的 RAG 项目。链路是：数据采集与清洗 -> 文档切片 -> 向量化入库 -> 检索召回 -> 重排 -> 大模型生成 -> 结果评估。工程重点不在“把模型调通”，而在稳定可控：我们做了多路召回（关键词 + 向量）、结果重排、引用来源透出、以及输出结构化约束。线上治理上加入了兜底策略：检索不足时降级为模板输出，并打标进入人工回流。最终让回答可解释性和命中率同时提升。

**高频追问：**
- RAG 和纯大模型直答相比提升在哪里？
- 如何控制幻觉？
- 你怎么证明效果变好了？

---

## 2) RAG 的召回策略怎么设计？

**口述主答（60~90 秒）：**  
我会采用“分层召回 + 统一重排”。第一层关键词召回保证精确命中，第二层向量召回提升语义覆盖，第三层业务规则补充时效性和权限过滤。召回后统一重排，综合相关性分、时效分、可信度分。这样做的原因是单一路径很难兼顾精度和召回。面试里我会强调：召回不是越多越好，关键是给重排提供高质量候选集。

**高频追问：**
- TopK 怎么选？
- 向量库和 ES 混合检索怎么做？
- 低质量文档污染怎么处理？

## 3) 你如何做 RAG 效果评估？

**口述主答（60~90 秒）：**  
我们分离线和在线两层评估。离线用标注集看 recall@k、MRR、答案完整性与引用正确率；在线看业务指标，比如采纳率、停留时长、人工改写率。为了避免“模型偶然发挥好”，我们会做分桶 A/B，并按问题类型拆分评估。最终评估结论必须能指导优化动作，例如：召回不足就优化切片和 embedding，答案空泛就优化 prompt 与重排策略。

**高频追问：**
- 标注集如何构建？
- 如果离线好在线差怎么办？
- 如何防止评估作弊（指标被刷）？

## 4) Function Calling 在 Agent 里怎么用？

**口述主答（60~90 秒）：**  
Function Calling 本质是“把模型决策和工具执行分离”。模型只决定“调用哪个工具、参数是什么”，真正执行由后端工具层完成。这样能把权限控制、幂等、审计、重试都放在可控系统里。我们会限制函数白名单、参数 schema 校验和调用次数，防止模型误调用或越权。工程上这比让模型直接自由生成 SQL/命令安全得多。

**高频追问：**
- 如何防止 prompt 注入导致越权调用？
- 工具超时或失败时怎么处理？
- 函数结果如何回填到上下文？

## 5) 多 Agent 协作的价值与风险？

**口述主答（60~90 秒）：**  
多 Agent 的价值是把复杂任务拆成专业角色，比如检索 Agent、分析 Agent、总结 Agent，提高复杂任务成功率。风险是链路更长、成本更高、调试更难。我的做法是只在“单 Agent 无法稳定完成”的任务中启用多 Agent，并加状态机约束和中间结果验证。简单任务坚持单 Agent，避免过度设计。

**高频追问：**
- 你怎么判断是否要上多 Agent？
- 如何控制 token 成本？
- 多 Agent 死循环怎么防？

---

## 6) 口述模板：当面试官问“你做过最难的 LLM 工程问题是什么？”

**参考表达（60 秒）：**  
最难的问题通常不是模型不够强，而是“业务稳定性和效果波动”并存。我的解法是把链路拆成可观测模块：召回、重排、生成、后处理分别埋点，定位问题来源；再通过灰度和 A/B 验证优化是否真实有效。最终我们把问题定位从凭经验变成了有数据证据，迭代速度和上线稳定性都提升了。
